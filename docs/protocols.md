# 外设 HID 电量协议实测记录

> 本文是社区对自家设备电量协议的实测整理，仅供个人设备研究与新设备适配参考。
> 所有帧格式来自对本人物品的抓包与真值校验，不针对任何厂商，也不保证适用于同型号的所有固件版本。
> 适配新设备请参考 `devices/template.json` 与 `core/sniffer.py`（应用内置一键嗅探向导）。

## 通用要点

- 2.4G 接收器通常暴露一个**供应商专有 HID 集合**（UsagePage 0xFF01 / 0xFF02 等），
  电量走这个集合，而不是标准 Battery Usage 页。
- Windows 上 `hidapi` 读到的首字节是 **Report ID**。
- 查询命令写入的长度必须与设备期望严格一致（含 Report ID 补齐）。
- **不要调用 `get_feature_report`**：部分固件会因此挂起 USB 端点，导致官方驱动也无法通信。
- 设备休眠时接收器可能返回 `pct == 0` 或直接不回包，应用层应保留最后已知值并标注来源。

## 凌豹 K98 机械键盘（Compx 2.4G 接收器）

- VID/PID：`0x3554` / `0xFA09`，电量通道 Col01（UsagePage=0xFF02 / Usage=0x0002）
- 按需查询（写入输出报告）：

  ```
  13 05 01 00 0A 03 + 补零到 64 字节
  ```

- 电量帧（输入报告）：

  ```
  13 0A 01 00 04 05 <pct> 01 00 ... <sum>
  ```

  `byte[6]` = 电量百分比；校验和为前若干字节求和（代码中未强校验，靠帧头匹配）。
- ⚠️ FR06（Col06）的 `06 00 02 64 64 64 9B 59 4B` 是恒定硬件信息，
  数值恒为 100，**不是电量**，必须忽略——这是最容易被误认成电量的帧。

## 迈从 G3 V2 无线鼠标（YJX-CHIP 方案）

- VID/PID：`0x3837` / `0x4245`（另有 `0x100A`、`0x4018` 变体），通道 UsagePage=0xFF01 / Usage=0x0010
- 主动查询（写入，严格 65 字节，首字节 0x00 为 Report ID）：

  ```
  00 55 30 A5 0B 2E 01 01 01 + 补零到 65 字节
  ```

- 电量帧（输入报告）：

  ```
  AA 30 A5 0B 0A 01 01 01 <pct> <chg> ...
  ```

  `byte[8]` = 电量百分比，`byte[9]` = 充电状态（1 = 充电中）。
- 实测查询后 20ms 内回包；回包 `pct == 0` 表示设备休眠。
- 官方驱动（MCHOSE HUB）运行时该通道**并未被独占**，可以共存直读，无需退出。

## 适配新设备的建议流程

1. 用 Wireshark + USBPcap 抓包，或直接使用本应用内置的「嗅探并添加新外设」向导；
2. 找出电量出现的字节偏移——重点排除"恒定不变"的伪电量帧（见 FR06 教训）；
3. 用系统蓝牙/官方驱动的读数做真值校验，至少覆盖高、中、低三档；
4. 确认查询命令的精确长度，写长或写短都可能无响应；
5. 按 `devices/template.json` 写配置，`protocol` 选 `standard_hid` 并填 `protocol_custom` 偏移。
